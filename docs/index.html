Pivoting & Scaling Policies for Half-Precision LU

Adaptive pivoting policies and exact power-of-two dynamic scaling that keep LU factorization inside the narrow FP16 dynamic range — combining partial pivoting's low search overhead with numerical stability on modern GPU Tensor Cores.

Algorithmic Formulation

Pivoting Policies & Per-Step Growth Bounds

Every rule is analyzed through the unified per-step growth law Lk+1 ≤ (1 + μk·αk)·Lk, where μk bounds the multiplier and αk bounds the pivot-row tail. Each policy defines a specific pair (μk, αk).

RuleMultiplier μₖTail Bound αₖGrowth bound ρ

Dynamic Scaling (DS)
Panel-diagonal magnitude is monitored as a lightweight O(w) proxy for trailing-block overflow risk, triggering an exact power-of-two column rescaling — exponent-only, zero rounding error in the significand while values remain in the FP16 normal range.
Empirical Evaluation

Dynamic Scaling Effectiveness & Numerical Stability

Across benchmark test matrices at τ = 1.01, dynamic scaling substantially increases finite refined-error coverage across matrix × method configurations:

Without Dynamic Scaling26 / 63
With Dynamic Scaling (DS)55 / 63
Numerical Limits
  • pores_2, west1505 — strongly pivot-dependent (Rook / Complete pivoting required).
  • b2_ss — unsolved across all tested policies, with or without dynamic scaling.
  • On dense synthetic matrices, dynamic scaling enables successful factorization; highly ill-conditioned systems remain bounded by condition number, not representable range.

Core Finding: Exposing adaptive pivoting and scaling independently provides greater solver versatility than enforcing a single rigid classical default.

Artifact Reproduction

Quick Reproduction (< 30s) & GPU Execution Suite

Full Open-Source Artifact
All CUDA source codes, benchmark harnesses, reproduction scripts, and ground-truth CSV datasets are included in this repository under open licenses (Apache 2.0 for code, CC-BY-4.0 for data). 
git clone https://github.com/snima/halfLU.git
cd halfLU
python -m pip install -r requirements.txt   # numpy scipy pandas matplotlib

# 1. Fast CPU-only reproduction (< 30 seconds): regenerates all tables & figures
make quick-reproduce
# Alternatively: bash scripts/run_all_figures_and_tables.sh

# 2. Compile standalone CUDA validation kernels (NVIDIA GPU required)
make kernels CUDA_ARCH=sm_70

# 3. Build high-performance Tensor Core benchmark suite (reaches 38.16 TFLOPS on V100)
make high-perf
./high_perf_cuda/build/high_perf_lu_benchmark --n 2048 --method PP

A single unified driver reproduces all tables and figures from verified ground-truth data:

bash scripts/run_all_figures_and_tables.sh

The high-performance GPU engine operates in native FP16 arithmetic with Tensor Core acceleration (`cublasGemmEx` with FP32 accumulator registers) and asynchronous dual-stream lookahead factorization.
